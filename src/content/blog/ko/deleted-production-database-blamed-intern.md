4월의 어느 목요일 밤 11시 42분, 중견 핀테크 스타트업의 수석 소프트웨어 엔지니어가 4개의 터미널 창을 띄워두고 있었습니다.

그는 스키마 마이그레이션을 테스트하기 위해 스테이징(Staging) 데이터베이스를 초기화하려 했습니다.

불과 4초 만에, 회사의 메인 PostgreSQL 클러스터에서 3년 치 실제 운영 결제 장부, 암호화된 고객 KYC 인증 내역, 활성 가맹점 프로필이 영구 소멸했습니다:

```sql
DROP DATABASE prod_customer_v2 CASCADE;
```

"정말 삭제하시겠습니까?" 같은 확인 팝업은 없었습니다. 2인 승인 절차도 없었습니다.

그리고 다음 날 오전 11시 30분, 회사는 책임을 지고 해고당할 대상을 찾아냈습니다. 입사한 지 사흘 된 21세의 대학생 인턴이었습니다.

---

## 무너진 안전망

기술적 재난은 잘못 입력된 단 한 줄의 명령어에 그치지 않았습니다.

수석 엔지니어가 재해 복구 파이프라인을 확인했을 때, 회사의 자동 AWS S3 백업은 IAM 수명주기 정책 만료로 인해 **최근 6주 동안 조용히 실패**하고 있었습니다. 그 백업 복구 티켓을 몇 달 전 '낮은 우선순위'로 분류해 둔 장본인 역시 시니어 개발팀이었습니다.

데이터는 소멸했고, 특정 시점 복구(PITR) 스냅샷은 존재하지 않았습니다.

그날 오후, 신규 입사한 인턴 데이비드는 API 쿼리 타임아웃 문제를 디버깅하기 위해 스테이징 DB 접근 권한을 막 발급받은 상태였습니다. 데이비드는 회사 슬랙(`#dev-general`) 채널에 로컬 psql 클라이언트 연결에 대해 질문 몇 개를 남겨두었습니다.

접근 제어가 분리되지 않은 프로덕션 서버는 직접 터미널 세션의 접속자 IP를 감사 로그로 남기지 않았습니다. 사내 메신저에 남은 유일한 공개 기록은 인턴이 DB 접속 자격 증명에 대해 질문했던 대화뿐이었습니다.

## 아침 스크럼의 결말

다음 날 오전 9시 2분, 사내 모니터링 경보가 울렸습니다. API 게이트웨이가 500 에러를 뿜어냈고, 고객 대시보드가 하얗게 마비되었습니다.

긴급 소집된 임원 회의에서 경영진은 지난밤 데이터베이스를 건드린 사람이 누구인지 즉각적인 소명을 요구했습니다.

백업 부재와 터미널 오작동을 솔직히 보고하는 대신, 슬랙 기록이 증거로 제시되었습니다. 인턴이 DB 접속 정보를 물어본 직후 승인되지 않은 명령어가 실행되었다는 설명이었습니다.

인턴 데이비드는 자신은 로컬 도커(Docker) 환경에서만 테스트 쿼리를 실행했을 뿐이라고 해명했습니다. 그러나 이사회에 보고할 즉각적인 희생양이 필요했던 임원진 앞에서, 수석 엔지니어의 확신에 찬 증언은 기술 감사 로그 대조 없이 사실로 받아들여졌습니다.

데이비드는 오전 11시 30분 회사 슬랙에서 강제 퇴장당했고, 추천서도 없이 그날 오후 불명예 해고되었습니다.

## 침묵의 대가

회사는 결제 대행사 웹훅 로그와 은행 정산 내역을 바탕으로 약 6억 원의 외주 비용을 들여 6주 동안 고객 장부를 수동 재구축했습니다.

이 사건은 신입 개발자의 권한을 제한해야 한다는 교훈적 사내 사례로 공식 문서화되었습니다. 2년 뒤, 해당 수석 엔지니어는 인프라 총괄 이사로 승진했습니다.

## 아키비스트의 판결

> **아키비스트의 분석:**  
> 
> 1. **표면적 실수:** 개발자가 검증되지 않은 로컬 터미널 창에서 실제 운영 데이터베이스를 대상으로 `DROP DATABASE CASCADE`를 실행한 것.
> 2. **실제 실패 원인:** 개발자 개인 노트북에서 감사 로그나 2인 승인 절차 없이 운영 데이터베이스를 삭제할 수 있도록 방치된 인프라와, 6주 동안 모니터링되지 않은 백업 실패.
> 3. **합리적인 사람들이 이를 방치한 이유:** 기술적 실수를 즉각적인 해고와 커리어 사형 선고로 다루는 징벌적 조직 문화 속에서, 솔직한 고백보다 자기보신과 침묵이 합리적인 선택으로 작동함.
> 4. **돌이킬 수 없는 지점:** 다음 날 아침 9시 15분, 경영진이 기술적 접속 로그 포렌식 검증 없이 사건을 종결짓기 위해 주니어 인턴을 향한 비공식 지목을 그대로 승인한 순간.
> 5. **최종 책임을 진 주체:** 영문도 모른 채 불명예 해고를 당하고 커리어에 상처를 입은 무고한 인턴. 반면 시스템적 결함과 원인 제공자는 조직 내에서 승진을 거듭함.
> 6. **불편한 교훈:** 실수를 솔직하게 밝히는 것보다 은폐하는 것이 더 안전한 조직은 결코 안전해질 수 없다. 그 조직은 다음 재난이 발생했을 때도 시스템을 고치는 대신 또 다른 희생양을 찾아낼 뿐이다.
