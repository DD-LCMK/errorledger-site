## 무슨 일이 일어났는가

2024년 7월 19일 금요일 새벽 04:09 UTC.

사이버 보안 대기업 크라우드스트라이크(CrowdStrike)의 클라우드 서버에서 작은 크기의 구성 파일 하나가 자동으로 배포되었습니다. 파일 이름은 `Channel File 291`. 크기는 고작 **14킬로바이트**였습니다.

배포가 시작된 지 몇 분 지나지 않아, 전 세계 850만 대 이상의 윈도우(Windows) PC와 서버가 일제히 치명적인 블루스크린(BSOD)을 띄우며 멈춰 섰습니다.

영국 방송국 스카이 뉴스의 생방송 화면이 꺼졌습니다. 런던 증권거래소의 시스템이 마비되었습니다. 미국 911 긴급 전화망이 다운되었고, 델타 항공을 비롯한 전 세계 주요 항공사의 항공편 5,000편 이상이 결항되며 공항 체크인 카운터에서는 직원들이 손으로 탑승권을 쓰는 진풍경이 벌어졌습니다.

단 78분 만에 글로벌 경제는 추정 **50억 달러(약 6조 8,000억 원)** 이상의 손실을 입었습니다.

## 치명적인 14KB 파일의 비밀

크라우드스트라이크의 대표 제품인 '팰컨(Falcon)' 센서는 윈도우 운영체제의 가장 깊은 심장부인 **링 0(Ring 0) 커널 레벨**에서 작동합니다. 커널 모드에서 실행되는 드라이버는 운영체제의 모든 메모리와 하드웨어에 무제한으로 접근할 수 있지만, 단 한 줄의 코드라도 오류를 일으키면 시스템 보호 장치 없이 운영체제 전체가 즉각 강제 종료(크래시)됩니다.

문제의 `Channel File 291`은 명명된 파이프(Named Pipes)를 이용한 악성코드 공격을 감지하기 위한 규칙 파일이었습니다. 

이 파일 내부에는 21개의 입력 매개변수를 요구하는 새로운 위협 규칙이 포함되어 있었습니다. 하지만 크라우드스트라이크의 커널 드라이버(`csagent.sys`)는 과거 버전을 기준으로 **20개의 매개변수만 읽도록 설계**되어 있었습니다.

드라이버가 존재하지 않는 21번째 매개변수 메모리 주소(`0x0000009c`)를 읽으려고 시도하는 순간, 잘못된 메모리 참조로 인한 커널 페이지 폴트(`PAGE_FAULT_IN_NONPAGED_AREA`)가 발생했습니다.

컴퓨터는 즉시 사망했습니다.

## 카나리 배포 없는 무조건적 자동 업데이트

더 충격적인 사실은 배포 과정에서 드러났습니다.

대부분의 엔터프라이즈 소프트웨어는 1%의 장비에 먼저 배포해 문제를 확인한 뒤 점진적으로 확대하는 **카나리(Canary) 배포** 방식을 사용합니다. 

그러나 크라우드스트라이크는 이 14KB짜리 채널 파일을 "신뢰할 수 있는 데이터 파일"로 분류하여, 자동 업데이트가 활성화된 전 세계 수백만 대의 서버와 워크스테이션에 **단 한 번에 동시 전송**했습니다.

내부 검증 도구(Content Validator) 역시 버그가 있어 이 잘못된 구성 파일을 정상 파일로 승인한 채 통과시켰습니다.

## 원격 복구 불가능: 주말을 반납한 수만 명의 IT 엔지니어

이 사고의 가장 잔혹한 점은 복구 방식이었습니다.

컴퓨터가 켜지자마자 부팅 단계의 커널에서 블루스크린이 떴기 때문에, 컴퓨터는 인터넷에 연결할 수도, 원격 패치를 다운로드할 수도 없었습니다.

유일한 해결책은 **물리적 접촉**뿐이었습니다.

IT 엔지니어가 전 세계의 고장 난 컴퓨터마다 직접 걸어가서, 안전 모드로 부팅한 뒤, 문제의 `C-00000291*.sys` 파일을 수동으로 삭제해야만 했습니다. 수만 명의 전산 엔지니어들이 USB 메모리를 들고 공항 바닥과 병원 책상 밑을 기어 다니며 주말을 보내야 했습니다.

## 아키비스트의 판결

> **아키비스트의 분석:**  
> 사건 이후 크라우드스트라이크와 언론은 이 재난을 "단순한 소프트웨어 메모리 버그"로 축소하려 했습니다. 하지만 그것은 본질을 가리는 편리한 변명입니다.
>
> 진짜 실패는 7월 19일 새벽에 일어난 것이 아닙니다. 전 세계의 병원, 항공사, 금융기관이 단 한 곳의 보안 업체에 무제한 커널 권한과 검증 없는 자동 배포 파이프라인을 쥐어주는 IT 구조를 용인했을 때 이미 시작된 비극이었습니다.
>
> 당신의 컴퓨터 핵심부를 외부 업체가 동의 없이 원격으로 업데이트하도록 방치한다면, 그것은 보안을 구매한 것이 아니라 '단일 실패 지점(SPOF)'을 외주 준 것에 불과합니다.
